# dsh-study-demo

给 DeepSeek Harness（DSH）讲题用的「学习演示面板」插件：模型讲解题目或知识点时，把一份**自包含的 HTML 演示**（Canvas 2D / WebGL、可拖可播、带时间轴与曲线）推送到 DSH 界面的**右侧边栏**并自动展开 —— 演示在右边，讲解文字还在对话里，两者并排看。

仓库里除了插件本体，还带一套**可复现的无头自检流程**（`tools/`）：推送前先在无头浏览器里把演示渲染出来，自动判定残影、白屏、越界、命名规范，并出帧图供人眼复核。踩过的坑都写进了 `演示流程.md` 的故障手册。


## 环境要求

| 项目 | 要求 |
|------|------|
| 运行时 | DeepSeek Harness (DSH) 0.1.x |
| Node.js | ≥ 20 |
| 前置插件 | 无 |
| 插件自身依赖 | 无（零外部依赖、零构建） |
| 自检工具依赖 | `@napi-rs/canvas`（只有 `tools/` 用得到，装法见下） |

## 行为

| 环节 | 行为 |
|------|------|
| 模型调用 `demo` 工具 | 把 `html` 写到工作区的 `.dsh-demo/<标题>.html` |
| 调用落定瞬间 | 浏览器侧调用框架的 `openFile()`，右侧边栏自动展开并渲染这份 HTML |
| 重复调用同一标题 | 覆盖同一个文件、侧边栏里是同一个标签页（**所以内容变了要换编号**） |
| 演示页面运行位置 | 不透明来源的 sandbox iframe：能用 Canvas 2D / WebGL2 / rAF / pointer 事件；不能访问宿主页面、localStorage、父窗口 |
| 打不开时 | 工具卡片上有「在侧边栏打开」按钮；渲染失败会在演示页里显示中文错误，不留白屏 |

## 命名规则（硬规则）

`demo` 工具的 `title` **同时就是文件名**，格式固定为：

```
科目-册/专题-章节/范畴-知识点-编号
```

**① 确实是官方教材内容**（人教版 / 北师大版 / 苏教版 / 外研版……某一册某一章）→ 照教材写：

```
数学-选择性必修一-空间向量-空间向量的加减-01
地理-选择性必修一-大气的运动-冷锋过境-02
语文-必修上册-第六单元-劝学论证思路-01
```

**② 不是教材内容**（跨章节专题、拓展、考法总结、竞赛科普）→ 第 2 段写 `专题`，第 3 段写内容范畴：

```
物理-专题-时空观-绝对空间与水桶实验-01
英语-专题-动词时态-过去进行时与when从句-01
```

- **拿不准算不算教材内容时，一律用「专题」形式**：宁可少写一个册名，也不要写错册章。
- 文件名、HTML 里的 `<title>`、`demo` 的 `title` **三处必须完全一致**（自检脚本会查）。
- 改了内容就换编号（`-01` → `-02`），不要用同一个标题覆盖。

## 安装（装配进 web profile）

### 方式 A：GitHub 装配（推荐）

本仓库已提交全部产物（`lib/`），git 装配**免构建**：

```bash
dsh plugin --profile web add github:HokkaidoCOLA/dsh-study-demo
```

本包 `package.json` 声明了 `dsh.bundle.patch`，安装后自动并入 profile 的 bundle 层并激活（无需手动编辑 `cordis.patch.yml`）。装配后**重启 `dsh web`** 生效。

### 方式 B：本地源码装配（开发调试）

```bash
cd dsh-study-demo
dsh plugin --profile web add "$(pwd)"
```

改完 `lib/` 下的文件重启 `dsh web` 即可（没有构建步骤：浏览器侧是手写的 CJS 工厂模块，`__ModuleLoader__.load` 直接加载 `lib/client.js`）。

### 配置覆写

在 profile 的 `cordis.patch.yml` 里按 id 覆写，或直接改：

```yaml
- id: dsh-study-demo
  config:
    maxHtmlBytes: 2000000
```

## 配置项

| 项 | 默认 | 说明 |
|----|------|------|
| `maxHtmlBytes` | `800000` | 单份演示 HTML 的字节上限；超限时 `demo` 工具报错、不落盘。要让内联数据更大的演示通过就调大它（代价是侧边栏打开变慢） |

## 模型侧工具

`demo` 工具三个参数：

| 参数 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 演示标题，**必须按上面的命名规则写**；它同时是文件名与侧边栏标签页名 |
| `html` | 是 | 完整 HTML 文档（`<!doctype html>` 开头），样式与脚本自包含、**零外部依赖** |
| `focus` | 是 | 一句话说明这份演示在展示什么，显示在工具卡片上 |

写演示的硬要求（时间轴六条、窄栏版式、`window.__probe` 契约、每帧 `clearRect`……）见 `演示流程.md`。

## 自检流程（这个仓库的真正重点）

推送演示前先在无头环境里渲染、判定、出图 —— 因为「数值全对但看起来是错的」只有看图才能发现。

```bash
cd tools && npm install --cache /tmp/npmcache   # 装 @napi-rs/canvas（--cache 不能省：沙箱下 ~/.npm 不可写）
node tools/check-demo.mjs ../.dsh-demo/<演示>.html 400 240
echo $?                                        # 0 = 全过；1 = 有失败，别推送
node tools/diag-demo.mjs <演示>.html            # 首帧抛错时，打印演示自己捕获的错误
```

`check-demo.mjs` 判定六项（任一不过即退出码 1）：

| 检查项 | 阈值 |
|--------|------|
| 命名规范 | 文件名匹配 `科目-册/专题-章节/范畴-知识点-编号`；第 2 段非册名且非「专题」→ 告警 |
| 错误面板 | `#err` 必须为空（首帧抛错会让后面每帧静默失败） |
| 残影 | 「先画 t0 再画 t1」与「干净画布只画 t1」**逐像素相同** |
| 画面变化（定帧检测） | 相邻帧变化 ≥ 0.8%；**只能排除定帧，证明不了「场景在动」** |
| 墨迹 | ≥ 800 非透明像素（否则是白屏） |
| 出界 | 文字 ≤ 2px（严格）；图形 ≤ 40px（宽容） |

> 是否「真的在动」只能靠人眼：**把游标和高亮遮住，画面里还剩什么在动？** 答案是「没有了」就不是动态演示。帧图出在 `tools/shots/`。

## 目录结构

```
lib/                 插件本体
  index.js             宿主侧：注册 demo 工具、写文件、算路径
  client.js            浏览器侧：工具卡片 + 调用 openFile 展开侧边栏
  index.d.ts           宿主侧类型声明
tools/               自检工具（不入库 node_modules 与帧图）
  check-demo.mjs       六项检查 + 退出码 + 出帧图
  diag-demo.mjs        打印演示自身捕获的错误
演示流程.md            五步流程 / probe 契约 / 判定阈值 / 故障手册 / 命名规则 / 推送清单
AGENTS.local.md        给 AI 读的硬规则（命名格式、推送前必须自检）
cordis.patch.yml       bundle patch：安装后自动激活本插件
```

## 开发

```bash
# 冒烟：拿任一演示跑一遍自检
node tools/check-demo.mjs <演示.html>

# 插件本身没有测试框架；改动后用 demo 工具推一份演示、看侧边栏是否自动展开
```
